## 2. v2.1 Token Optimization Rules (High Context Efficiency)

1. **Offload Batch Title Insertion to `scripts/build_resolve_timeline.py`:**
   - **Do NOT** call `timeline(action="insert_fusion_title")` 80 times in 80 separate conversation turns. That creates a massive conversation transcript and consumes hundreds of thousands of tokens.
   - **Instead**, run `python3 scripts/build_resolve_timeline.py <plan.json> --timeline <name>`. The script connects directly to DaVinci Resolve, creates/updates the multi-track timeline, appends camera cuts, places all 50–80 native `Text+` caption clips on Track `V4` (with lower-third positioning, ultra-tight line spacing, and pure white text), and places focus words on Track `V2` in **~1 second**, returning a compact JSON summary to chat.
2. **Never Echo Full Raw Transcripts in Chat:**
   - Transcripts can be 50,000+ characters. Keep full transcripts in `transcripts/` or `assembly_words.json` on disk. In chat, show only structured 5–10 line summary tables of selected beats and timecodes.
3. **Targeted Frame Captures for Visual QA:**
   - When inspecting visually with `timeline_frame(action="capture")`, cap `max_width: 1280` or `960` and sample only 4–6 key milestone timestamps (Hook, Lower-third, Caption, Behind-speaker word, Jump cut, CTA).

## 3. Non-Negotiable Coordinate, Index & ID Rules

| Rule | Detail | Trap / Consequence if Violated |
|---|---|---|
| **`track_index` is 1-based** | `track_index: 1` is `V1` / `A1` / `ST1`. | Passing `0` fails or targets the wrong track. |
| **`item_index` is 0-based** | `item_index: 0` is the **first** clip on that track (`timeline(action="get_items")` list index). | Passing `1` skips the first clip on the track. |
| **Copy `clip_id` verbatim** | Always copy the exact hex UUID from `folder(action="get_clips")` or `media_pool` output. | Never type a `clip_id` from memory; a single transposed hex char silently breaks downstream calls. |
| **Source Frames vs. Record Frames** | In `clip_infos` (`create_timeline_from_clips`, `append_to_timeline`), `start_frame` and `end_frame` are **source media frames** in `source_fps`, with `end_frame` **exclusive** (`duration_source_frames = end_frame - start_frame`). | Feeding record (timeline) frames into `start_frame`/`end_frame` places the wrong portion of the camera file with no error. |
| **Audio WAV Frame Rate Freeze** | Standalone `.wav`/`.mp3` files have no intrinsic video FPS and freeze the project's `timelineFrameRate` at import time. | Always set `timelineFrameRate` via `project_manager(action="safe_set_project_settings")` **before** importing audio, and read `source_fps` per clip rather than assuming 24fps. |
| **Timeline Start Frame (`01:00:00:00`)** | Resolve timelines start at `01:00:00:00` by default (`86400` @ 24fps, `90000` @ 25fps, `108000` @ 30fps). | In `create_timeline_from_clips`, `record_frame` is relative to timeline start by default (`record_frame_mode="relative"`), whereas raw Resolve `recordFrame` is absolute (`timeline_start_frame + offset`). Always use `scripts/build_resolve_plan.py` and verify with `timeline(action="clip_where")`. |
| **Visual Frame Verification** | `get_thumbnail` returns a static per-clip thumbnail (identical for every frame of that clip). | Always use `timeline_frame(action="capture", params={"timecode": ..., "quality": "preview"|"frame", "max_width": 1280})` or `gallery_stills(action="grab_and_export")` on the Color page to inspect what Resolve actually renders. |

## 4. Native Text & Caption Architecture (v2.1)

### Spoken Captions on Track `V4_CAPTIONS_ANIMATED`
- **Native Resolve `Text+` Clips:** Generated by `scripts/build_resolve_timeline.py`.
- **Lower-Third Placement:**
  - Vertical 9:16: **Line 1 at `Center Y = 0.33`**, **Line 2 at `Center Y = 0.265`** (Single line at `Center Y = 0.30`).
  - Landscape 16:9: `Center Y = 0.18 to 0.25`.
  - Speaker's face, neck, and upper torso remain 100% visible and unobstructed.
- **Ultra-Tight Zero-Gap Line Spacing:** Vertical line offset is `~0.065`, creating tight stacked headline typography with zero vertical gap.
- **Color & Shading:**
  - `Text Fill (1)`: Pure White (`#FFFFFF`).
  - `Outline (2)`: Thin dark border (`Enabled2 = 1, Thickness = 0.004, OutsideOnly = 1`).
  - `Soft Shadow (3)`: Gentle drop shadow (`Enabled3 = 1, Opacity = 0.65, Softness = 0.020, Position = {0.003, -0.004}`).
- **Inspector Editable:** Every clip on Track V4 has its `Name` set to the spoken text and clip color set to `Orange`. A human editor can click any clip in Resolve, open the Inspector panel, and modify words, fonts, or colors immediately!

### Behind-Subject Focus Words on Track `V2_BEHIND_SUBJECT_GFX`
- **Native Resolve `Text+` Clips:** Large display typography (`Size 0.17 to 0.24`, `Center Y ~0.64`).
- **Color & Shading:** Pure White (`#FFFFFF`) with soft drop shadow.
- **Matte on Track `V3_SPEAKER_ROTO_MATTE`:** Duplicate camera cut isolated via Resolve AI **Magic Mask** or DeltaKeyer (keyed to background color). Clip color: `Purple`.

## 5. Non-English Spoken Language Protocol (v2.1)

If footage is non-English:
1. **Transcribe Native Speech Autonomously:** Run `faster-whisper` (model: `large-v3`) with `--language <detected>` or Resolve AI transcription.
2. **Present 4 Clear Transcript Formatting Options in Step 0 Intake (Q9):**
   - **(A) Native Script:** (e.g. Hindi Devanagari, Tamil, Malayalam, Spanish, Japanese, German)
   - **(B) Romanized / Transliterated:** (Latin-alphabet transliteration, popular for high-retention social reels)
   - **(C) English Translation:** (Translated into English while preserving spoken phrase timing)
   - **(D) Dual Captions:** (Top line: Native script; Bottom line: English translation)
3. **Do not make assumptions**; follow the user's explicit selection.
